# PAI

Document question answering over German documents, with citations, a confidence-gated
human review queue, and an evaluation harness that runs in CI.

**Status:** in development. See `PLAN.md` for the build plan.

## What it does

Point it at a folder of PDFs. It parses them, indexes them, and answers questions in
German with citations pointing at the exact page used. When retrieval is weak or the
answer isn't grounded in the retrieved text, the case is routed to a human review
queue rather than answered with a guess. Corrections from review feed back into the
evaluation set.

The engine is corpus-agnostic. Documents belong to a named collection with its own
config and its own evaluation set. The first collection is TU Darmstadt
Prüfungsordnungen and Modulhandbücher.

## Why the evaluation matters

RAG systems fail quietly. A prompt tweak or a provider-side model update can cost
fifteen percent of accuracy with no error and nothing in the logs. Every change in
this project is measured against a hand-written gold set of 50 question-answer pairs,
each with its known source page, covering four categories:

| Type | What it measures |
|---|---|
| lookup | the answer sits in one passage |
| multihop | requires combining two sections |
| paraphrase | user vocabulary differs from the document's |
| unanswerable | does the system abstain instead of inventing an answer |

The gold set is written by hand and never generated by a model.

## Stack

Python 3.12 (uv) · FastAPI · Postgres 16 + pgvector · sentence-transformers
(multilingual-e5-base, local) · Gemini Flash · pytest · ruff

Runs at zero cost: embeddings are local, inference uses free-tier APIs.

## Setup

```bash
git clone https://github.com/<your-user>/PAI.git
cd PAI
uv sync
cp .env.example .env    # add your API key
docker compose up -d
docker compose exec -T db psql -U app -d pai < sql/schema.sql
```
